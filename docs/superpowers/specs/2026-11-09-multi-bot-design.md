# 複数Bot（最大10個）を同時に動かす 設計書

作成日: 2026-11-09
状態: レビュー待ち
土台: [2026-10-23-android-python-runner-design.md](2026-10-23-android-python-runner-design.md)（以下「10/23設計書」）

## 1. 目的と背景

今のアプリは、10/23設計書の「まず1個で動くか確かめる」ためのお試し版のままです。持てるBotは1つだけです（内部名 `spike`、共有フォルダ名 `MyBot`）。

ユーザーは、スマホ1台ですべてを済ませたいと考えています。今は紬を含めて2個ですが、目標は10個です。そこで今回、10/23設計書の複数Bot部分を作ります。

ユーザーがいちばん大事にしていること（ユーザーの言葉）: **「一番大事なのはぱっと誰でも理解できること」**。仕組みを理解していなくても使えることを求めています（ユーザー自身も「実は自分もよく理解していない」と話しています）。

## 2. 目標・非目標・アンチゴール

### 目標
- Botを複数（10個を目標）持ち、それぞれを独立して起動・停止・再起動できる。
- ホーム画面を開けば、すべてのBotの起動状況がひと目で分かる。
- Botのファイルの置き場所が、ファイルアプリ・PC・このアプリのどこから見ても同じ形になっている。
- 今使っているBot（紬）が、アップデート後もそのまま動く。

### 非目標（今回はやらない。次の段階で作る）
- 落ちたときの自動再起動（10/23設計書 6.3 の待ち時間を伸ばす方式）。
- スマホを起動したときのBotの自動起動。
- 秘密の値の暗号化（Android Keystore）。
- ログのファイル保存と上限、ログに出た秘密の値の伏せ字。
- import文からのパッケージ推測。
- Botの並べ替え、メモリ使用量の表示。

この4つ（自動再起動・自動起動・暗号化・ログ）は10/23設計書で決めた機能ですが、まだ作っていません。**今回は複数起動だけを作り、スマホで試してから次に回します**（私の判断。ユーザーは「おすすめの方で」と任せた）。

### アンチゴール（動いていても失敗とみなすもの）
- 初めて見た人が、どのBotが動いているか、ファイルがどこにあるか迷う画面。
- 1つのBotの停止・エラー・取り込みが、ほかのBotを止めたり壊したりすること。
- アップデートで、今のBotのファイル・秘密の値・ライブラリが消えること。
- 秘密の値が共有フォルダや画面に平文で出ること（今と同じ扱いを保つ）。
- 他のアプリが、動いているBotのコードを書き換えられること（金庫の方式を保つ。6章）。

### 受け入れた制約（ユーザーが決定）
- このアプリのBotは、すべて同じアプリの権限で動きます。そのため、あるBotのプログラムは、ほかのBotのファイルや秘密の値を読めてしまいます。Botごとに完全に分けるには作りを根本から変える必要があるため、今回は分けません。中身を信用できるBotだけを入れて使う前提です（ユーザー:「このままでいい」）。

## 3. 用語

- **Bot**: 名前のついた1つのPythonプログラムです。ファイル、最初に実行するファイル、秘密の値、ライブラリ、ログを持ちます。
- **共有フォルダ**: `ドキュメント/PythonRunner/<Bot名>/` です。ユーザーが見て直せる場所です。
- **金庫**: アプリ専用の領域にある、実際に動かすファイルです。ユーザーには見せません。

## 4. 画面

### 4.1 ホーム画面（ユーザーが見本を見て「かなりいいね」と合意済み）

上から順に並べます。

1. **アプリ名**（Python Runner）。右上に「⚙」ボタンを置き、アプリ全体の設定（4.4）を開きます。
2. **まとめ**: 「稼働中 1 / 3」「エラー 1」「停止中 1」の3つの数字です。稼働中は緑、エラーは赤で表示します。
3. **Botのカード**（1Bot＝1枚）。カードには次のものを載せます。
   - 状態の点: 緑＝稼働中、灰＝停止中、赤＝エラーで停止。起動中は黄色にします（私の判断）。
   - Bot名。
   - 状態の文字: 「稼働中 3時間12分」「停止中」「エラーで停止」「起動中…」。
   - 起動ボタン、または停止ボタン。
   - 最新のログ2行。エラー行は赤で表示し、ログが無いときは何も出しません。
   - フォルダの場所: 「📁 ドキュメント › PythonRunner › 紬」。
   - エラーで止まったカードは、枠も赤くします。
   - 共有フォルダとの食い違いがあるときは、その表示を出します（6.4）。
4. **「＋ Botを追加」ボタン**（4.3）。
5. **見つかった新しいフォルダ**（6.5）。あるときだけ表示します。

- カードは、追加した順に並べます。状態で並べ替えると、カードの位置が動いて迷うためです（私の判断）。
- カードをタップすると、そのBotの詳細画面（4.2）が開きます。
- Botが1つも無いときは、「最初のBotを追加しましょう」という説明と「＋ Botを追加」ボタンを出します。

### 4.2 Botの詳細画面（10/23設計書 5.2 を土台にする）

- 上部には、戻るボタン、Bot名、状態の点と文字、稼働時間、そして「起動／停止」「再起動」ボタンを置きます。
- タブは4つです。中身は、今の1画面の各セクションを移します。

| タブ | 中身 | 今の画面のどこから移すか |
|---|---|---|
| ログ | そのBotのログ全件、コピー、消去 | 6. ログ |
| ファイル | 📥 取り込む、ファイル一覧（Explorer）、最初に実行の表示、場所の表示 | 2. Botのファイル |
| ライブラリ | pip install／アンインストール／requirements.txt から一括、作業の出力 | 3. ライブラリ |
| 設定 | 最初に実行するファイル、秘密の値、Bot名の変更、Botの削除 | 4. 秘密の値 ほか |

- **ファイルタブ**:
  - 一番上に「📍 ドキュメント › PythonRunner › 紬」と表示します。
  - 一覧は金庫の中身ですが、並びは共有フォルダと同じになります（6章）。
  - 秘密のファイル（`.env` など、`FolderSync.isSecret` に当たるもの）には「🔒 アプリの中だけ（フォルダには出ません）」と表示します。今あるファイルとフォルダの食い違いを、画面で説明するためです。
- **設定タブの「最初に実行」**: Bot内の .py ファイルから選びます。今と同じく、Explorer で選ぶ方式でかまいません。
- 今ある説明（Help）は、それぞれのタブへ一緒に移します。

### 4.3 Botの追加

1. 「＋ Botを追加」を押します。
2. 今の「📥 取り込む」と同じメニューを出します（ファイルを選ぶ／フォルダを選ぶ）。
3. 取り込みが終わったら、名前の確認を出します。
   - 名前の初期値（私の判断）: フォルダを選んだならフォルダ名、ZIPなら拡張子を除いたファイル名です。.py なら拡張子を除いたファイル名にします。
   - 最初に実行するファイルの初期値は、`BotImporter.pickMain` で選びます。
4. 「追加する」を押すと、Botが一覧に加わり、そのBotの詳細画面が開きます。
5. requirements.txt があれば、ライブラリタブに今と同じ「まとめて入れる」案内を出します。

- 名前の確認でやめた場合、取り込んだファイルは捨てます。そのとき、一覧にも共有フォルダにも何も残しません。
- 取り込みの途中経過（%）、100MB以上も断らないこと、空き容量の確認は、今の取り込みと同じです。

### 4.4 アプリの設定（⚙）

今の「1. Pythonの準備」と「7. 端末の設定」を移します。どちらもBotごとではなく、アプリ全体の設定だからです。

## 5. Botの名前

- 前後の空白は取り除きます。空の名前は使えません。長さは40文字までです（私の判断）。
- フォルダ名に使えない文字（`/ \ : * ? " < > |` と制御文字）は使えません。`.` で始まる名前も使えません。
- 同じ名前のBotは作れません（大文字・小文字の違いは同じとみなします）。
- 共有フォルダに、一覧に無い同名フォルダが既にある場合も使えません。その場合は「同じ名前のフォルダがあります」と表示します。
- **名前を変えると、共有フォルダの名前も変わります。** 変えられなかったときは名前を元に戻し、理由を表示します。
- 動いているBotの名前も変えられます。動いているのは金庫の中身なので、影響はありません。

## 6. ファイルの置き場所（ユーザー合意済み：「今のところこの案で」）

### 6.1 見える形

```
ドキュメント/PythonRunner/   ← Botのフォルダだけが並ぶ（アプリは他に何も置かない）
├─ 紬/                       ← フォルダ名 ＝ アプリでのBot名
│  ├─ persona.txt
│  ├─ requirements.txt
│  └─ src/bot.py
└─ 音楽Bot/
   └─ main.py
```

1. フォルダ名はBot名と同じにします。
2. 中身は取り込んだままの形にします。アプリはファイルを足しません。ライブラリ、ログ、設定、記録用のファイルはアプリの中だけに置きます。
3. アプリのファイルタブも、同じ並びで見せます。
4. フォルダに出ない秘密のファイルは、出ないことを画面に表示します（4.2）。
5. 共有フォルダとアプリの中身がずれたら、カードに表示します（6.4）。

### 6.2 金庫（アプリの中）

- 今の考え方（金庫で動かし、共有フォルダはコピー、反映はユーザーが確かめてから）はそのまま残します。
- 見えるフォルダから直接動かす案は採りません。Android 8 では他のアプリがフォルダを書き換えられ、トークンを抜かれる危険があるためです（ユーザーに説明済み）。
- Botごとの置き場所は、内部IDで分けます（私の判断）。IDは名前と関係なく、名前を変えても変わりません。
  ```
  filesDir/bots/<id>/code/       金庫（実際に動かすファイル）
  filesDir/bots/<id>/libs/       ライブラリ
  filesDir/bots/<id>/shared.manifest
  filesDir/bots/<id>/import-staging/, import-backup/
  ```
- Botの数に上限は設けません。10個は目標であって、上限ではありません（私の判断）。11個目を追加するときは、一度だけ「10個を超えると、スマホによっては動きが重くなることがあります」と表示します。
- Botの一覧（ID、名前、追加した順）は、アプリ内のファイル1つに保存します。書き込みは、一時ファイルに書いてから名前を変える方式にし、途中で落ちても壊れないようにします。
- Botごとの設定（最初に実行、秘密の値、稼働中だったか）は、IDを含めたキーで保存します。

### 6.3 今のBotの引っ越し（アップデート時に1回）

- 今のBotは、名前「MyBot」で一覧の1個目になります。今の共有フォルダ `PythonRunner/MyBot` とそのままつながります。名前はあとから変えられます。
- 引っ越すもの: `bots/spike` → `code/`、`bots/spike-libs` → `libs/`、`bots/spike-shared.manifest`、最初に実行、秘密の値、稼働中だったか。
- 引っ越しは、途中で落ちてもやり直せるように作ります。何度実行しても同じ結果になり、ファイルも秘密の値も失いません。
- 引っ越しは、サービスがBotを動かす前と、画面を開く前の両方で確実に終わらせます。
- 取り込みが途中で止まっていた場合（`import-backup` の目印）は、先に今の方式で元に戻してから引っ越します。

### 6.4 共有フォルダとのずれの表示（今の自動の確認を複数Bot向けにする）

- アプリを開いている間は、今と同じく約4秒ごとに確認します。対象は全Botの共有フォルダで、変化の目印は `fingerprint` を使います。
- 変更があるBotのカードと詳細画面には、「✏ 変更あり」と表示します。タップすると、今と同じ一覧（追加・変更・削除）と「反映する／反映しない」が出ます。
  - 今は、変更を見つけると自動でダイアログが出ます。10個あると何度も出てしまうため、カードに表示する方式に変えます（私の判断）。見つけるのは今どおり自動で、反映は今どおり確かめてから行います（ユーザー合意済み）。
  - 「反映しない」を選んだ変更は、同じ内容のままならもう表示しません。
  - 動いているBotに反映したら、今と同じく「今すぐBotを再起動しますか？」と聞きます。
- **共有フォルダがまるごと無くなった場合**は、全ファイルの削除として扱いません。カードには「📁 フォルダが見つかりません」と表示し、「フォルダを作り直す」（金庫の中身をもう一度書き出す）を出します。金庫の中身は消しません。
- 共有ストレージの許可が無いときは、今と同じく共有フォルダを使わずに動きます。

### 6.5 一覧に無いフォルダ（10/23設計書 6.5 より）

- `PythonRunner/` に、一覧に無いフォルダがあるときがあります（PCで作った場合など）。そのときはホーム画面の下に「新しいフォルダが見つかりました：○○」と「追加する」を表示します。
- 「追加する」を押すと、そのフォルダを取り込み元として 4.3 の追加の流れに入ります。名前の初期値はフォルダ名です。
- 追加するまでは、そのフォルダには何もしません。
- **そのフォルダは、コピーせずにそのままBotの共有フォルダになります**（私の判断）。
  - 中身を金庫へ取り込みます。取り込んだ内容を「同期済み」として記録するので、追加した直後に「✏ 変更あり」は出ません。
  - 名前の確認で名前を変えた場合は、そのフォルダの名前を変えます。フォルダ名とBot名を同じにするためです。
  - このフォルダ自身の名前は、5章の「一覧に無い同名フォルダ」の決まりから外します。
  - 名前の確認でやめた場合は、フォルダには何もしません。中身も名前もそのまま残ります。
  - 秘密のファイル（`.env` など）は、今の同期と同じく金庫へ取り込まず、フォルダにそのまま残します。トークンは「秘密の値」に入れる、という今の考え方を保ちます。
- 4.3 で選んだフォルダの名前が、一覧に無い共有フォルダと同じ場合は、5章の決まりで止めます。そのとき「このフォルダはホーム画面の『新しいフォルダが見つかりました』から追加できます」と案内します（私の判断）。

## 7. Botの実行

- **Botごとに別のOSプロセス**で動かすのは今と同じです。1つのBotが落ちても、ほかのBotには影響しません。
- フォアグラウンドサービスは1つにして、その中でBotごとに `BotRunner` を持ちます。サービスは、どれか1つでも動いている間だけ続けます。
- 起動・停止・再起動は、BotのIDを付けてサービスに伝えます。再起動を待っている状態（今の `restartRequested`）も、Botごとに持ちます。
- 常駐通知には「2個のBotが稼働中」のように数を出します。タップするとアプリが開きます。
- **エラー通知はBotごとに出します**: 「『紬』がエラーで停止しました」。別のBotの通知で上書きしないようにします。
- ウェイクロックは、どれか1つでも動いている間は持ち続け、全部止まったら手放します。
- システムにサービスを終了させられた場合は、「稼働中だった」Botだけを起動し直します（今の `wasRunning` をBotごとに持つ）。
- 起動の前には、そのBotの止まった取り込みを元に戻します（今の `recoverImportNow` と同じ）。

## 8. 取り込み・pip・ログ

- **取り込み**: 今の仕組み（staging → plan → apply、目印による巻き戻し）を、そのBotの置き場所でそのまま使います。同時に行う取り込みはアプリ全体で1つだけにします（私の判断）。取り込み中は、ほかのBotの「📥 取り込む」と「＋ Botを追加」を押せなくし、「ほかのBotの取り込み中です」と表示します。
- **pip**: そのBotの `libs/` に入れます。同時に行うpipの作業も、アプリ全体で1つだけにします（私の判断）。秘密の値はpipに渡しません（今と同じ）。
- **ログ**: Botごとに、今と同じメモリ上のログを持ちます。ファイルへの保存は次の段階です。

## 9. Botの削除（10/23設計書 5.2・6.5 より）

- 削除は、設定タブの「このBotを削除」から行います。確認ダイアログで次の2つから選びます。
  - 「一覧から外すだけ（フォルダは残す）」← 初期選択
  - 「フォルダも削除する」
- どちらを選んでも、動いているBotは先に止めます。金庫の中身、ライブラリ、秘密の値、設定は消します。ダイアログには「秘密の値も消えます」と書きます。
- 「フォルダは残す」を選んだ場合、そのフォルダは次から 6.5 の「新しいフォルダ」として表示されます。

## 10. 確かめ方

- 名前の決まり、一覧の保存と読み込み、引っ越し（途中で落ちた場合を含む）、Botごとの置き場所、フォルダが無くなったときの扱いは、JVMの単体テストで確かめます。
- 複数のBotの起動・停止・再起動の管理も、Androidに依存しない部分を切り出して単体テストを書きます。
- 画面は、ビルドとlintで確かめたうえで、ユーザーが実機（ZenFone 4／AQUOS sense6）で試します。
- 配布は試験版 `v0.6.0-test1` として出します。

## 12. 私（Claude）の判断で決めたこと（ユーザーの確認待ち）

- 今回は複数起動だけを作り、自動再起動・自動起動・暗号化・ログ保存は次の段階に回すこと。
- カードは追加した順に並べること。起動中の点を黄色にすること。
- 名前の決まり（40文字まで、使えない文字、大文字小文字を区別しない重複チェック）。
- 追加時の名前の初期値（フォルダ名／ファイル名）。
- 共有フォルダの変更を、自動ダイアログではなくカードの「✏ 変更あり」で知らせること。
- 共有フォルダがまるごと無くなっても、削除として扱わないこと。
- 取り込みとpipは、アプリ全体で同時に1つずつにすること。
- 今のBotを「MyBot」という名前で引っ越すこと。
- 削除時は、金庫の中身・秘密の値も消すこと。
- 見つかったフォルダは、コピーせずにそのままBotの共有フォルダにすること（6.5）。
- Botの数に上限を設けず、11個目で一度だけ注意を出すこと。
