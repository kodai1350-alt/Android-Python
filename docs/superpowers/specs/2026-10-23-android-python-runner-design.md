# Python Runner（Android）設計書

作成日: 2026-10-23
状態: レビュー待ち

## 1. 目的と背景

ユーザーは現在、iPadのPython実行アプリでDiscord Botなどを動かしている。しかしiPadでは画面を消したりアプリを閉じたりするとBotが止まってしまう。

そこで、手元のAndroid端末を「Botサーバー代わり」に置きっぱなしにして、**画面オフでもPythonスクリプトを動かし続けられるアプリ**を作る。

ユーザーが大事にしていること（ユーザーの言葉より）:

1. **分かりやすいUI**。これが一番大事。ファイルの場所なども含めて、とにかく分かりやすく、認識しやすいこと。
2. 画面を消していても動き続けること。
3. 複数のBotを同時に動かせること。

## 2. 利用者と利用シーン

- 利用者はユーザー本人のみ（一般公開アプリではない）。
- 実行対象は、常時動かし続けるPythonスクリプト。主にDiscord Bot（discord.py）。
- Botのコードは、スマホに持ってきたファイルをアプリに取り込む。
- ライブラリは、iPadのときと同じようにpipで入れる。

## 3. 対象端末

- 実機: ASUS ZenFone 4（ASUS_Z01KDA / ZE554KL）、Android 8、arm64。
- サポート範囲: Android 8.0（API 26）以上、arm64-v8a のみ。32ビットとx86は対象外。

## 4. 目標・非目標・アンチゴール

### 目標
- 複数のPythonスクリプト（Bot）を、それぞれ独立して起動・停止・再起動できる。
- 画面オフ・アプリを閉じた状態でも動き続ける。
- アプリ内でpip installできる。
- 各Botのログ（stdout / stderr）をアプリ内で見られる。
- Botのファイルの場所と構成が一目で分かる。

### 非目標（今回はやらない）
- Google Playでの配布。
- iOS対応、32ビット端末への対応。
- 本格的なコードエディタ（IDE）機能。補完やデバッガは作らない。
- C拡張を含むライブラリが必ず動くことの保証。
- PCやWebからの遠隔操作。
- 端末の外への通知（Discord Webhookなど）。ユーザーが「いらない」と判断。
- Discordのボイス機能（PyNaCl・opus・ffmpeg）や、Pillow・numpyなどネイティブ部品が必要なライブラリへの対応（v1では対象外。6.4参照）。
- 複数ユーザー向けの機能。

### アンチゴール（動いていても「失敗」とみなすもの）
- どこに何があるか分からない、操作に迷うUI。
- Botが知らないうちに止まっていて、アプリを開いても気づけない（ホームの赤表示とスマホの通知で分かること）。
- トークンなどの秘密の値が、画面に平文で出たりログに漏れたりする。

### 成功の基準
- ZenFone 4で、discord.pyのBotを2つ以上、画面オフのまま24時間以上動かし続けられる。
- Botが落ちたら自動で再起動され、そのことがアプリと通知で分かる。

## 5. 画面（ユーザーがモックアップで確認・合意済み）

UIの言語は日本語。

### 5.1 ホーム画面（案C：ダッシュボード＋ログ）
- 上部にサマリーを表示する。例:「2 / 4 稼働中　エラー 1」。
- Botごとにカードを1枚表示する。カードの内容:
  - 状態の点（緑=稼働中、灰=停止中、赤=エラーで停止）
  - Bot名
  - 起動ボタン、または停止ボタン
  - 最新ログ数行（黒背景。エラー行は赤）
- 右下に「＋ 追加」ボタンを置く。
- カードをタップするとBotの詳細画面に移る。

### 5.2 Botの詳細画面
- 上部に、状態、稼働時間、「再起動」ボタン、「停止」ボタン（停止中なら「起動」ボタン）を表示する。
- 4つのタブ:
  - **ログ**: stdout / stderr を全件表示する。新しい行が来たら自動でスクロールする。コピーと共有ができる。エラー行は赤で表示する。
  - **ファイル**: 5.4を参照。
  - **ライブラリ**: そのBotに入っているパッケージの一覧を表示する。pip install（パッケージ名を入力）とアンインストールができる。requirements.txtから一括でインストールすることもできる。インストール中の出力も表示する。
  - **設定**: 以下を扱う。
    - 最初に実行するファイル（例: main.py）
    - 落ちたら自動再起動（ON/OFF）
    - スマホ起動時に自動起動（ON/OFF）
    - 秘密の値（環境変数。名前と値の組。値は伏せ字で表示）
    - Bot名の変更
    - Botの削除

### 5.3 Botの追加画面
1. **Botのファイルを選ぶ**: 「zipファイルを選ぶ」「フォルダを選ぶ」「.pyファイルを選ぶ」の3つから選ぶ。
2. **名前と起動ファイル**: Bot名を入力し、最初に実行するファイルをプルダウンで選ぶ。main.py や bot.py があれば、それを初期値にする。
3. **ライブラリ**: requirements.txt があれば「見つかりました」と表示し、中身を一覧で見せる。そのまま一括インストールできる。
4. 「追加する」ボタンを置く。

### 5.4 ファイルタブ（分かりやすさ最優先）
- 画面上部に、いま表示しているフォルダの場所を常に表示する。例:「📍 ドキュメント › PythonRunner › 音楽Bot」。
- 最初に実行するファイルは、緑の帯と「▶ 最初に実行」バッジで強調する。
- ファイルの種類はアイコンで見分けられるようにする: 🐍 .py、📁 フォルダ、🔑 .env（「秘密の値」バッジ）、📋 requirements.txt、⚙️ その他の設定ファイル。
- サブフォルダは、インデントでツリー表示する。
- サイズと更新日時を表示する。
- .env の中身は、タップするまで伏せ字にする。
- 下部に「＋ 追加」「⇄ 差し替え」「📂 開く」の3つのボタンを置く。「開く」はテキストファイルを簡易エディタで開く。

### 5.5 初回起動時の案内（私の判断）
画面オフで動き続けるには、端末側の設定が必要になる。そのため、初回起動時に次の設定を順番に案内する画面を出す。
- ストレージへのアクセス許可
- 通知の許可
- 電池の最適化の除外
- ASUS独自の省電力機能（自動起動マネージャーなど）でアプリを許可すること

各項目に、「設定を開く」ボタンと、済んだかどうかのチェック表示を付ける。この案内は、設定メニューからいつでも見直せるようにする。

## 6. 中身の仕組み

### 6.1 技術スタック（私の判断）
- 言語: Kotlin。UI: Jetpack Compose。
- Python: **公式CPythonのAndroid版**（3.13以降。ビルド時点の最新安定版を推奨）を arm64-v8a 向けにアプリへ同梱する。
- pip: 同梱のPythonに付属する pip を使う。

### 6.2 Botの実行
- **Botごとに別のOSプロセス**でPythonを動かす。1つのBotが落ちたりフリーズしたりしても、他のBotやアプリ本体を巻き込まないようにするため。停止時はプロセスを終了させる。
- 作業ディレクトリは、そのBotのフォルダにする。
- stdout と stderr はアプリが受け取り、ログとして保存する。`PYTHONUNBUFFERED=1` を指定し、出力が即座に届くようにする。
- 「設定 > 秘密の値」は、環境変数として渡す。Botフォルダ内の .env を読むかどうかは、Bot側のコード（python-dotenv など）に任せる。
- SSL証明書: discord.py などのHTTPS通信が動くよう、証明書（certifi など）を同梱し、`SSL_CERT_FILE` 等で設定する。
- Pythonの実行ファイルをどう起動するかは、ビルドする人に任せる（10章を参照）。ただし、新しいAndroidで禁止されている「アプリのデータ領域にある実行ファイルを直接実行する方式」は避け、将来のAndroidでも動く方式を選ぶこと（例: ネイティブライブラリ領域に置く）。

### 6.3 常時稼働
- Botが1つ以上動いている間は**フォアグラウンドサービス**を動かし、常駐通知を出す（例:「Python Runner：2個のBotが稼働中」）。
- CPUが眠らないよう、パーシャルウェイクロックを保持する。
- サービスがシステムに終了させられた場合は、再開できるようにする。
- 「落ちた」の定義（私の判断）: v1では**プロセスが終了したこと**だけを検知する。動いているのに固まっている状態（ハング）の検知はv1では行わない。
- **自動再起動**（設定でONのBot）: 異常終了したら自動で再起動する。短時間に繰り返し落ちる場合は、待ち時間を伸ばしながら再試行する（例: 5秒→30秒→2分→最大10分）。
- **スマホ起動時に自動起動**（設定でONのBot）: 端末の起動完了を受け取って起動する。
- **エラー通知（私の判断）**: Botがエラーで止まったときや自動再起動したときに、スマホに通知を出す。端末の外（Discordなど）には通知しない（ユーザーの判断）。

### 6.4 ライブラリ（pip）
- ライブラリは**Botごとに別々**に管理する。Bot同士でバージョンが衝突しないようにするため。
- インストール先は**アプリの内部領域**にする。共有ストレージには、ネイティブコードを読み込めない制約があるため。
- Pythonだけで書かれたパッケージは問題なく入る想定。
- C拡張を含み、Android用のwheelが無いパッケージは失敗しうる。その場合は「このライブラリはAndroidでは使えない可能性があります」と分かりやすく表示する。
- discord.py の依存パッケージ（aiohttp、yarl、multidict、frozenlist、propcache など）は、C拡張なしの純Python版で動くようにする。`AIOHTTP_NO_EXTENSIONS=1` などの環境変数を設定し、純Python版でインストールさせる。
- **確認必須**: discord.py の最新版が、アプリ内pipで入ってZenFone 4で動くこと。
- **v1の対応範囲（私の判断）**: ユーザーは既存Botが使うライブラリを覚えていない。そのためv1は「PyPIから純Pythonで入るもの＋文字ベースのdiscord.py」を対象にする。ボイス機能（PyNaCl・opus・ffmpeg）やPillow・numpyなどは対象外とし、Android用wheelを自前でビルド・配布する仕組みは作らない。将来、実際に必要になったら別途検討する。
- **import文からの推測（私の判断）**: Bot追加時に requirements.txt が無い場合は、.pyファイルの import 文を読み取って、入れるべきパッケージ候補を表示する（例:「discord → discord.py」）。インストールするかどうかはユーザーが選ぶ。対象外のライブラリ（PIL、numpy、nacl など）が見つかった場合は、「Androidでは動かない可能性があります」と事前に警告する。

### 6.5 ファイルの保存場所（ユーザー合意済み）
- Botのファイルは共有ストレージの `ドキュメント/PythonRunner/<Bot名>/` に置く。Googleの「ファイル」アプリなど、ほかのアプリからも直接見たり差し替えたりできるようにするため。
- zip、フォルダ、.py から取り込むと、この場所にコピーされる。
- Android 8 では、ストレージの読み書き権限を実行時に求める。Android 11以上では「全ファイルへのアクセス」の許可を案内する（Google Playで配らないので問題ない）。
- アプリの内部領域に置くもの:
  - Botの一覧
  - 各Botの設定
  - 秘密の値
  - ライブラリ
  - ログ
- 秘密の値は、Android Keystore を使って暗号化して保存する（私の判断）。
- **Bot一覧の正（私の判断）**: アプリ内部の一覧を正とする。各Botは内部IDで管理し、フォルダ名とは結び付けて記録する。
  - ホーム画面を開くたびに `PythonRunner/` フォルダを確認する。
  - 一覧に無いフォルダが見つかった場合は、「新しいフォルダが見つかりました：追加しますか？」と案内する。
  - 登録済みのフォルダが消えたり名前が変わったりした場合は、カードに「フォルダが見つかりません」と表示する。そのうえで、フォルダを選び直すか、一覧から外すかを選ばせる。
- **Botの削除（私の判断）**: 削除時に確認ダイアログを出し、「一覧から外すだけ（ファイルは残す）」と「ファイルも削除する」を選ばせる。初期選択は「ファイルは残す」。

### 6.6 ログ
- Botごとにファイルへ保存する。上限を決めてローテーションする（例: 1Botあたり最大5MB）。
- 秘密の値として登録された文字列がログに出た場合は、表示時に伏せ字に置き換える（私の判断）。

## 7. 配布（ユーザー合意済み）

- このアプリ専用の**新しいGitHubリポジトリ**を作る。
- リポジトリは**公開**にする（私の判断）。スマホのブラウザからログインなしでReleasesをダウンロードできるようにするため。Botのコードやトークンはリポジトリに含まれない。
- **GitHub Actions** でAPKをビルドする。タグをpushしたら、署名済みのリリースAPKを**Releases**ページに添付する。
- 署名鍵はGitHub Secretsに保管する。毎回同じ鍵で署名し、アップデートを上書きインストールできるようにする。
- インストール手順（「提供元不明のアプリ」の許可など）を README に日本語で書く。
- このPCにはAndroid SDKが入っていない。そのため、ビルドはGitHub Actionsで行う前提にする。
- **役割分担（私の判断）**:
  - ユーザーはGitHubのWebでリポジトリを作り、URLを伝える。
  - 署名鍵はビルドする側が作り、GitHub Secretsへ登録する手順を用意する。
  - 署名鍵のバックアップはユーザーが保管する。鍵を失うとアップデートを上書きインストールできなくなるため、READMEにも明記する。
- **進め方（私の判断）**: 最初に「お試し版」をReleasesに出す。お試し版は、同梱Pythonでdiscord.pyのBotを1つ動かせるだけの最小構成とする。ユーザーがZenFone 4に入れて、動いたかどうかを報告する。動くことが確認できてから、UI全体を作る。24時間連続稼働の確認もユーザーが実機で行う。

## 8. ユーザーが決めたこと
- 用途: Discord Bot などを常時動かす。
- 画面オフで動作する。複数のBotを同時に動かす。分かりやすいUIを最優先にする。
- 配布はGoogle Playではなく、GitHubからダウンロードしてインストールする。
- Botのコードはアプリとは別に、ファイルとして取り込む。1つのBotが複数ファイルのフォルダでもよい。
- ライブラリはアプリ内のpipで入れる。
- ホーム画面は案C（ダッシュボード＋ログ）。詳細画面、追加画面、ファイルタブの構成はモックアップのとおり。
- ファイルは、ほかのアプリからも見える共有ストレージに置く。
- 新しいGitHubリポジトリを作る。
- Botが止まったことを、端末の外（Discordなど）に通知する機能はいらない。
- 既存Botが使っているライブラリは覚えていない。

## 9. 私（Claude）の判断で決めたこと
- Kotlin＋Jetpack Compose、公式CPythonのAndroid版、Botごとに別プロセスで動かすこと。
- サポート範囲を Android 8以上・arm64のみにすること。
- 初回起動時の権限・省電力設定の案内画面。
- エラー時の通知と、自動再起動の待ち時間の伸ばし方。
- ライブラリをBotごとに分けて、アプリの内部領域に置くこと。
- 秘密の値の暗号化と、ログでの伏せ字。
- リポジトリを公開にすること。
- アプリ名は仮に「Python Runner」とする。
- v1はボイス機能やネイティブ部品が必要なライブラリを対象外にすること。代わりに、import文から候補を出し、事前に警告すること。
- 「落ちた」はプロセス終了のみで判定すること。
- アプリ内部の一覧を正とし、フォルダとの食い違いを案内すること。削除時の初期選択は「ファイルは残す」にすること。
- リポジトリはユーザーが作り、署名鍵のバックアップはユーザーが保管すること。最初にお試し版で、実機でdiscord.pyが動くことを確認すること。

## 10. ビルドする人に任せること
- Pythonのマイナーバージョン（3.13以降）と、CPythonのAndroid版の入手方法（python.org の配布物を使うか、CIでビルドするか）。
- Pythonの実行ファイルの起動方式。ただし6.2の制約は守ること。
- 簡易テキストエディタの実装方法。
- アイコンや配色などの細かい見た目。ただし、モックアップの分かりやすさは保つこと。
- リポジトリ名。
- テストの方針。
