# ファイル画面を PC のエクスプローラーに寄せる 設計書

作成日: 2026-11-13
状態: ユーザーの確認待ち
土台: [2026-11-12-files-env-libraries-design.md](2026-11-12-files-env-libraries-design.md)（以下「11/12 設計書」）。`spike/node` の上で作る。

## 1. 目的と背景

ユーザーは、アプリのファイルの入れ替えや削除が PC と違う動きをすることに戸惑いました。求めているもの（ユーザーの言葉）:
- 「動作の仕組みをできるだけパソコン側に寄せて」
- 「可能な限りPCにほとんどの操作を寄せてほしい」
- ごみ箱、同じ名前のときの置き換え／スキップ、名前の変更・移動・コピー、まとめて選ぶ：「全部ほしい」
- 「タップで選ぶ・もう一度タップで開く」（スマホの普通とは逆）について：「PCに合わせて、それでいい」
- ファイルを開いたとき：「アプリの中でメモ帳みたいに見て直せるようにして」

アプリの絶対条件（ユーザーの言葉）:「見やすく、使いやすく、わかりやすく」。

お手本は **Windows 11 のエクスプローラーとメモ帳**。迷ったら、Windows で同じことをしたときの動きと言葉に合わせる。

## 2. 目標・非目標・アンチゴール

### 目標
- ファイル画面の操作が、PC のエクスプローラーと同じ考え方で使える。
- 削除してもごみ箱から戻せる。直前の操作を「元に戻す」で取り消せる。
- 同じ名前があるときは、Windows と同じ 3 択で聞く。
- 名前の変更・切り取り・コピー・貼り付け・新規作成・プロパティができる。
- 文字のファイルを、アプリの中のメモ帳で見て直せる。

### 非目標（今回はやらない）
- ドラッグ＆ドロップ、検索、表示の切り替え（アイコン表示など）。
- メモ帳の「元に戻す」・検索・置換・文字コード選択（キーボードの機能に任せる）。
- 画像・音声などのプレビュー。
- ZIP の作成・展開（取り込みでは今までどおり展開する）。

### アンチゴール（動いていても失敗とみなすもの）
- 確認なしに、元に戻せない形でファイルが消えること（ごみ箱を空にする・メモ帳で保存しないで閉じる、には確認を出す）。
- 操作の途中で失敗して、ファイルが半分だけ動いた状態で残ること。
- `node_modules`・`.venv` を手で消したり動かしたりできること（11/12 設計書のまま守る）。
- Bot のフォルダの外のファイルを、操作で消したり書き換えたりできること（リンクもたどらない）。
- スマホのいつものアプリに慣れた人が、選んでいるのか開いたのか分からなくなること（選んだものは必ず色と ☑ で分かるようにする）。

## 3. 操作の対応表（PC → このアプリ）

| PC | このアプリ |
|---|---|
| クリック（選ぶ） | タップ。選んだ項目は青くなり、左の □ が ☑ になる。ほかの選択は外れる |
| ダブルクリック（開く） | 選んである項目をもう一度タップ。フォルダは中へ、文字のファイルはメモ帳で開く |
| Ctrl＋クリック（追加で選ぶ） | 左の □ をタップ（ほかの選択は外れない） |
| Ctrl＋A（全部選ぶ） | ツールバーの「⋯」→「すべて選択」 |
| 右クリック | 長押し。押した項目が選ばれていなければ、それだけを選んでからメニューを出す |
| 何もないところをクリック | 一覧の空いた所をタップ → 選択を外す |
| ← → ↑ | アドレスバーの左の「戻る・進む・上へ」 |
| 列の見出しクリック（並べ替え） | 「名前・種類・更新日時・サイズ」の見出しをタップ。もう一度で逆順 |

- 前回入れた「長押しで削除」は、この長押しメニューの「削除」に置き換わる。
- 「戻る・進む」は、その Bot の画面を開いている間の移動の履歴。

## 4. ツールバーと長押しメニュー

### 4.1 ツールバー（Windows 11 の並び）
`新規 ▾`・`切り取り`・`コピー`・`貼り付け`・`名前の変更`・`削除`・`元に戻す`・`⋯`

- 使えないときは薄い色にする（選んでいないときの切り取り、クリップボードが空のときの貼り付けなど）。
- 画面が狭いときは、入りきらないものを `⋯` に入れる（並びの後ろから）。
- `⋯` の中: すべて選択・選択を外す・プロパティ・取り込む（フォルダ／ファイル）・Botをまるごと入れ替える。
- 今の画面上部にある「フォルダを取り込む」「ファイルを取り込む」「Botをまるごと入れ替える」のボタンは、ツールバーのすぐ上にそのまま残す（よく使うため。私の判断）。

### 4.2 新規
- 「フォルダー」→ 名前「新しいフォルダー」（あれば「新しいフォルダー (2)」…）
- 「テキスト ドキュメント」→「新しいテキスト ドキュメント.txt」
- 「Python ファイル」→「新しい Python ファイル.py」（私の判断。Bot づくりでよく使うため）
- 作るとすぐに名前の変更の入力欄を出す（Windows と同じ）。

### 4.3 長押しメニュー
- 開く・切り取り・コピー・名前の変更・削除・プロパティ。
- `.py` なら、仕切りの下に「▶ これを最初に実行」。
- 複数選んでいるときは「開く」「名前の変更」を出さない。
- `node_modules`・`.venv`（とその中）は「開く」「プロパティ」だけ（8.1 の 3）。

## 5. 各操作

### 5.1 名前の変更
- 入力欄。ファイルなら、最初は拡張子の前までを選んだ状態にする（Windows と同じ）。
- 使えない名前は、その場で理由を出して確定させない:
  - `/ \ : * ? " < > |`、空、`.` か `..`、同じフォルダの同じ名前（大文字小文字の違いだけなら許す）。
- 拡張子を変えたときは「拡張子を変更すると、ファイルが使えなくなる可能性があります。変更しますか？」（Windows と同じ文）。
- 「最初に実行するファイル」の名前を変えたり動かしたりしたら、「最初に実行」もついていく。

### 5.2 切り取り・コピー・貼り付け
- クリップボードはアプリ全体で 1 つ。**別の Bot にも貼り付けられる**（私の判断。PC で別のフォルダへ貼れるのと同じ）。
- 切り取りは、貼り付けるまで元の項目を薄く表示する。貼り付けたら移動になり、クリップボードは空になる。
- コピーを同じフォルダに貼り付けたときは「〇〇 - コピー」「〇〇 - コピー (2)」と名前を付ける（Windows と同じ）。
- フォルダを自分の中に貼り付けようとしたら、「対象のフォルダーは、元のフォルダーのサブフォルダーです」と出して止める。
- 時間がかかるときは、進み具合（何個中何個）と「キャンセル」を出す。キャンセルしたら、そこまでのものは元に戻す。

### 5.3 同じ名前があるとき（貼り付け・取り込み）
Windows と同じダイアログ:「ファイルの置換またはスキップ」「『player』には同じ名前のファイルが n 個あります」
- **ファイルを置き換える**
- **ファイルをスキップする**
- **ファイルごとに決める**：1 個ずつ、両方の大きさと更新日時を並べて、残す方にチェックする（両方チェックすると、新しい方を「名前 (2)」で入れる）。

フォルダ同士が同じ名前のときは、中身を合わせる（Windows の「フォルダーの統合」）。中の同じ名前のファイルについてだけ、上のダイアログで聞く。

- 11/12 設計書の「取り込む前に確かめてください」の「置き換わるもの」は、このダイアログに置き換わる。
- 「Botをまるごと入れ替える」の「今のBotにあって、新しいフォルダにないファイル（残す／削除する）」は残す。削除する場合は、ごみ箱に入れる。

### 5.4 削除とごみ箱
- 削除するとごみ箱へ移る。確認は出さない（Windows と同じ）。画面の下に「n 個の項目をごみ箱に移動しました」と「元に戻す」を数秒出す。
- ごみ箱は **Bot ごと**（アプリの中、`bots/<id>/trash/`）。左の並びに「ごみ箱 (n)」。
  - 一覧: 名前・元の場所・削除した日時・サイズ。
  - 「元に戻す」: 選んだものを元の場所へ戻す。元の場所に同じ名前があれば 5.3 のダイアログ。元のフォルダがなければ作り直す。
  - 「ごみ箱を空にする」「完全に削除」: 「完全に削除しますか？元に戻せません」と確認する。
- ごみ箱は「空にする」を押すまで残す（Windows と同じ。私の判断）。ただし、空き容量が足りなくなって取り込みなどができないときは、「ごみ箱を空にすると n MB 空きます」と案内する。
- Bot を削除したら、その Bot のごみ箱も消える。
- ごみ箱の中身は共有フォルダには出さない。ごみ箱に入れたファイルは共有フォルダからも消え、元に戻すと共有フォルダにも戻る（私の判断）。
- 「Botをまるごと入れ替える」で削除を選んだものも、ごみ箱に入る。

### 5.5 元に戻す
- 直前の操作から順に取り消せる（削除・移動・名前の変更・コピー・新規作成・貼り付けで置き換えたもの）。Bot ごとに最大 20 個まで（私の判断。範囲は 8.1 の 6）。
- 置き換えで上書きされた古いファイルは、ごみ箱に入れておき、元に戻すときに戻す。
- 取り消したあとにファイルが変わっていて戻せないときは、「元に戻せませんでした（ファイルが変わっています）」と出して、そこで止める。
- メモ帳での保存は、この「元に戻す」の対象にしない（保存前の中身はごみ箱に入れない）。

### 5.6 プロパティ
- 名前・種類・場所（「入退室音 › player」）・サイズ・中のファイル数とフォルダ数（フォルダのとき）・作成日時（取れる場合）・更新日時。
- 複数選んでいるときは、合計のサイズと数。
- 数えるのは画面を止めないで行う（大きなフォルダでも固まらない）。

## 6. メモ帳

- 文字のファイルを、もう一度タップ（または長押し →「開く」）で開く。
  - 文字のファイルかどうかは、中身で決める（最初の 8KB に 0 バイトがなく、UTF-8 か Shift_JIS として読める）。
  - それ以外は「このファイルは文字のファイルではないので、開けません」と、種類と大きさを出す。
  - 大きさの上限は 1MB（私の判断。古いスマホでも固まらないため）。超えると「大きすぎて開けません（1MB まで）」。
- 画面: 上にファイル名（変更があれば先頭に「*」、Windows と同じ）、`保存`、`閉じる`。下に行と列（「行 12, 列 5」）・文字コード（「UTF-8」「Shift_JIS」）・改行（「CRLF」「LF」）。
- 文字は等幅。自動の折り返しはオン（スマホの幅のため。私の判断）。
- 保存: 読んだときと同じ文字コードと改行で書く。途中で止まっても壊れないよう、一時ファイルに書いてから置き換える。保存後は共有フォルダにも写す。
- 閉じるとき・戻るときに保存していなければ、Windows と同じく「〇〇への変更内容を保存しますか？」「保存する／保存しない／キャンセル」。
- Bot が動いている間も開いて直せる。保存したら「Bot を再起動すると、この変更が使われます」と出し、「今すぐ再起動」ボタンを付ける（私の判断）。
- 設定タブの「.env」の「表示して編集」も、このメモ帳で開く。

## 7. Bot が動いている間の操作（私の判断）

PC では動いているプログラムのファイルも、たいてい操作できる。それに合わせて、動いている間も操作を止めない。ただし、
- ファイルが変わったら、今の取り込みと同じく「今すぐBotを再起動しますか？」と聞く（何回も聞かないよう、その画面にいる間は 1 回）。
- 部品を入れている間（workBusy）と取り込みの途中は、変更する操作（貼り付け・削除・名前の変更・新規・元に戻す）を薄くして使えなくする。
- 前の設計の「削除するには Bot を止めてください」はなくす（ごみ箱で戻せるため）。

## 8. 共有フォルダとの関係（変えない部分と、足す部分）

- 動くのはアプリの中のファイル。共有フォルダは写し（11/12 設計書のまま）。
- どの操作のあとも、共有フォルダへ写す（`export`）。移動・名前の変更は、共有フォルダでも同じように移動・名前の変更になる（古い名前のものは消え、新しい名前で出る）。共有フォルダ側で書き換えられていたファイルは消さない（今の決まりのまま）。
- フォルダを消したり移したりして空になった共有フォルダ側のフォルダは、一緒に消す（11/12 の残り課題 8 の解決）。ただし、中にアプリの知らないファイルがあれば残す。

## 8.1 レビューで決めたこと（すべて私の判断）

1. **共有フォルダに、まだ反映していない変更（✏ 変更あり）があるファイルを操作するとき**：
   操作する前に「この中に、PC などで変えて、まだ反映していないファイルがあります（一覧）」と出し、
   「先に反映する」（今の反映の画面を開く）か「キャンセル」を選ばせる。反映しないまま操作はしない。
   どちらの変更も黙って消えないようにするため。メモ帳で開くときも、そのファイルに未反映の変更があれば同じように聞く。
2. **ごみ箱を通す範囲**：ファイルを消したり上書きしたりする道は、**すべて**ごみ箱を通す。
   手で削除、貼り付けの置き換え、取り込み（フォルダ／ファイル）の置き換え、Botをまるごと入れ替える（上書きと削除の両方）、
   反映する（共有フォルダの変更で上書き・削除されるもの）。メモ帳の保存だけは通さない（5.5）。
3. **`node_modules`・`.venv` を含むフォルダ**：
   - そのフォルダの削除・移動・名前の変更はできる（中の部品も一緒に動く・ごみ箱に入る。同じスマホの中なので移すだけで速い）。
   - コピーするときは、`node_modules`・`.venv` を**コピーしない**（入れ直せるため。コピー先は「部品を入れる」で ✗ と出る）。
   - `node_modules`・`.venv` 自体の長押しメニューは「開く」「プロパティ」だけ（コピーもなし）。
   - 名前の変更・移動で、部品の記録（ライブラリタブの ✓）と「最初に実行」もついていく。
4. **Botをまるごと入れ替える**：1 つの画面のまま。「置き換え／スキップ」は聞かない（まるごと入れ替えるので、
   同じ名前は**いつも置き換える**。古い方はごみ箱へ）。画面に出すのは、置き換わる数・増える数と、今の
   「今のBotにあって、新しいフォルダにないファイル（残す／削除する）」。置き換わる数は、中身が同じものも含めて数える。
5. **大文字・小文字**：同じフォルダで、大文字・小文字だけが違う名前は**同じ名前として扱う**（ぶつかる）。
   共有フォルダ（と Windows）では区別されないため。例外は、その項目自身の名前の大文字・小文字だけを変える名前の変更（`a.py` → `A.py`）。
6. **元に戻すの範囲**：Bot ごとに、アプリが動いている間（アプリを完全に閉じるまで）覚えておく。タブや画面を移っても消えない。
   別の Bot から切り取って貼り付けた操作は、**貼り付けた側の Bot**の履歴に入り、元に戻すと元の Bot の元の場所へ戻る。

## 9. 決めたことのうち、ユーザーが決めたもの
- 操作はできるだけ PC（Windows）に合わせる。
- ごみ箱・置き換え／スキップ・名前の変更／移動／コピー・まとめて選ぶ、を全部入れる。
- タップで選ぶ、もう一度タップで開く（PC と同じ）。
- 文字のファイルは、アプリの中のメモ帳で見て直せる。

## 10. 私の判断（ユーザーに確認してもらうもの）
- 取り込みの 3 つのボタンは、ツールバーの上にそのまま残す。
- 新規に「Python ファイル」を足す。
- クリップボードはアプリ全体で 1 つで、別の Bot にも貼り付けられる。
- ごみ箱は Bot ごと、空にするまで残す。ごみ箱は共有フォルダに出さない。
- 元に戻すは、Bot ごとに最大 20 個、アプリを閉じるまで。
- メモ帳は 1MB まで、折り返しはオン、Bot の動作中も保存できて再起動を勧める。
- Bot が動いている間も、ファイルの操作を止めない。
- レビューで決めた 6 つ（8.1）：未反映の変更があるファイルは先に反映を求める、消す・上書きはすべてごみ箱を通す、部品はコピーしない、まるごと入れ替えは同じ名前をいつも置き換える、大文字小文字だけの違いは同じ名前、元に戻すはアプリを閉じるまで。

## 11. 作る人に任せること
- 画面の細かい配置・色・アイコン（今のアプリの見た目に合わせ、Windows の言葉を使う）。
- ごみ箱の中の保存の形（元の場所・日時を残せること、名前がぶつからないこと）。
- 操作の途中で失敗したときに元に戻す仕組み（11/12 の取り込みの印とバックアップの考え方を参考に）。
- 文字コードの見分け方の細部。
