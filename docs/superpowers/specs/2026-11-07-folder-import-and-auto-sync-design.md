# フォルダ・ZIPの取り込みと、共有コピーの自動反映 設計書

2026-11-07。AI（紬）はいったん後回しにして（`ai/askbot` ブランチに保管）、アプリ本体を仕上げる最初の作業。

## 1. 何のために作るか

今の「📄 .pyファイルを追加」は、.py を1つずつしか入れられない。実際のBotは `main.py` と `cogs/` フォルダ、`config.json` などが入ったフォルダで動くことが多い。ユーザーは、Googleドライブなどにあるフォルダをそのまま取り込んで動かしたい。

また、共有コピー（Documents/PythonRunner/MyBot）で変えたファイルは、「🔄 更新」を押さないと反映されない。押さなくても反映されるようにしたい。

## 2. やること（ユーザー決定）

### 2.1 取り込みのボタンは1つ
- 今の「📄 .pyファイルを追加」を **「📥 取り込む」** の1つにする。押すと2つから選ぶ。
  - **ファイルを選ぶ**：
    - `.py` は1つ追加する。
    - `.zip` は中身を展開して取り込む。
    - そのほかのファイル（config.json など）は、そのまま追加する。
  - **フォルダを選ぶ**：スマホの中のフォルダを、中身ごと取り込む。
- Googleドライブは、ほかのアプリにフォルダごと渡せないことが多い（作り手の判断、未確認）。そのため、Googleドライブのフォルダは「ダウンロードしてZIPにしたもの」を「ファイルを選ぶ」で取り込む使い方を、画面の説明で案内する。

### 2.2 2回目以降の取り込みは「同じ名前のファイルだけ上書き」
- 取り込んだファイルと同じ名前（同じ場所）のファイルは、新しいもので上書きする。
- Botフォルダにだけあるファイル（Botが作ったデータなど）は消さずに残す。

- **上書きされるファイルがあるときは、取り込む前に一覧で確かめる**（ユーザー決定）。
  - 「次のファイルは今あるものが新しい中身に置き換わります」と一覧を出す。
  - 「上書きして取り込む」を押したときだけ取り込む。
  - 上書きするファイルが1つもないときは聞かずに取り込む。
  - Botのデータ（data.json、bot.db など）が、配布物に入っている最初の状態で消されるのを防ぐため。

### 2.2.1 Botが動いている間の取り込み・反映（ユーザー決定）
- Botが動いている間も、取り込みと「反映する」はできる。
- 終わったら「今すぐBotを再起動しますか？（再起動するまで新しい中身は使われません）」と聞く。
  - 「再起動する」を押すと、Botを止めて起動し直す。
  - 「あとで」を押すと何もしない。

### 2.3 大きさの上限は付けない（ユーザー決定）
- その代わり、取り込む前に、スマホの空き容量が足りるか確かめる。足りなければ、何MB足りないかを出して取り込まない。
- 時間がかかるときは「取り込み中 〇%」を出す（作り手の判断）。

### 2.4 共有コピーの自動反映（ユーザー了承）
- 「🔄 更新」ボタンはなくす。
- **アプリ → 共有コピー**：取り込んだとき、削除したとき、Botが止まったときに、自動で写す（Botの停止時は今も写している）。
- **共有コピー → アプリ**：
  - アプリを開いたとき（画面に戻ったときも含む）と、開いている間の数秒おきに、共有コピーで変わったファイルがないか自動で確かめる。
  - 変わっていたら、ボタンを押さなくても「共有のコピーが変わっています」の一覧が出る。
- **「反映する」を押す確認は残す**（ユーザー了承）。共有コピーの場所はほかのアプリも書き換えられるため、知らない変更がトークン付きで動くのを防ぐ。
  - 「反映しない」を選んだ同じ変更で、何度も一覧を出さない。
  - 次に一覧を出すのは、さらに変更があったとき、または「起動」を押したとき（起動のときは今と同じく必ず確かめる）。

## 3. 作り手の判断で決めたこと（ユーザー了承ずみの提案）
- ZIPの中身が1つのフォルダに包まれていたら（GitHubの「Download ZIP」など）、外側のフォルダは外して取り込む。
- 「最初に実行」のファイルがまだ決まっていない、または消えているときは、自動で選ぶ。
  - 選ぶ順は main.py → bot.py → app.py → 一番上の階層にある .py が1つだけならそれ。
  - それでも決まらなければ、ファイル画面で選んでもらう（今と同じ）。
  - すでに決まっていて、そのファイルがあるなら変えない。
- 取り込まないもの：`__pycache__`、`.git`、`venv`、`.venv` の各フォルダ。
- `requirements.txt` が一番上の階層にあれば、その中身を「3. ライブラリ」の入力欄に入れておく。ユーザーは「インストール」を押すだけ。
- `.env` など秘密のファイル（今の `FolderSync.isSecret` の決まり）は、アプリ専用の場所にだけ入れ、共有コピーには出さない。今の決まりと同じ。
- 安全のため、Botフォルダの外に書き出すような名前（`../` など。いわゆる Zip Slip）は取り込まない。
- **取り込みは共有コピーにも強く書き込む**（作り手の判断）。
  - 取り込んだファイルは、共有コピーにまだ反映していない変更があっても、取り込んだ中身で共有コピーと目録（manifest）を上書きする。
  - そうしないと、取り込み直後の自動チェックで、共有コピーに残った古い中身が「変わっています」と出てしまう。そこで「反映する」を押すと、取り込んだばかりのものが古い中身で戻ってしまう。
  - 取り込みはユーザーがはっきり選んだ操作なので、こちらを優先する。差分の取り方そのもの（§5）は変えない。
- **取り込みの途中でアプリを離れても続ける**（作り手の判断）。
  - 取り込みはアプリ全体で動く処理にして、画面の回転や別アプリへの切り替えでは止めない。
  - 一時フォルダに全部用意してからBotフォルダへ移す。アプリそのものが終了させられたら、途中の一時フォルダは捨て、Botフォルダは取り込み前のまま残す。

## 4. こうなったら失敗
- Botが作ったデータ（保存ファイル、データベース）が、取り込みで消える。
- 取り込みの途中で失敗したときに、Botフォルダが中途半端な状態になり、動かなくなる。途中で失敗したら、それまでに上書きしたものも元に戻すか、取り込み前の状態のまま残す。
- 共有コピーの変更が、確認なしで実行用に入る。
- 確かめるのを数秒おきにすることで、電池を目立って減らす。アプリが画面に出ている間だけ確かめ、裏に回ったら止める。

## 5. 変えないもの
- Botは1つだけ（MyBot）。複数のBotは今回は扱わない。
- Botを動かす場所は、今と同じアプリ専用の場所。
- 共有コピーとの差分の仕組み（`FolderSync` の目録・ハッシュ）。

## 6. 作り手に任せること
- 「📥 取り込む」を押したときの選び方の見た目（メニュー、ダイアログなど）。
- 数秒おきの間隔（3〜5秒程度を想定）。
- ZIPの展開とフォルダのコピーの作り方（`ZipInputStream`、`DocumentsContract` など）。
- 途中で失敗したときの戻し方（一時フォルダに展開してから移す、など）。
- 進み具合の出し方。

## 7. まだ確かめていないこと
- Googleドライブのアプリが、フォルダ選び（Android の「フォルダを選ぶ」画面）に出てくるか。
- 大きなZIP（数百MB）の展開にかかる時間（ZenFone 4）。
