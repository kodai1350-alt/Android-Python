# ファイル画面・.env・ライブラリ表示の見直し 設計書

作成日: 2026-11-12
状態: ユーザーの確認待ち
土台: [2026-11-09-multi-bot-design.md](2026-11-09-multi-bot-design.md)（以下「複数Bot設計書」）。作業は `spike/node` ブランチの上で行う（入退室音Botが Node.js の試作版で動いているため。私の判断）。

## 1. 目的と背景

ユーザーが入退室音Botをスマホに移したとき、PCで直した新しいフォルダに入れ替えようとしました。ところがアプリではフォルダを削除できず、**Botを削除して最初から作り直しました**。作り直すたびに秘密の値（トークン）も入れ直しになります。

ユーザーがファイル画面を開く理由は3つです（ユーザーの言葉から）:
1. どこに何があるか確かめる
2. 中身（ファイル）を入れ替える
3. フォルダごと入れ替える

アプリの絶対条件（ユーザーの言葉）: **「見やすく、使いやすく、わかりやすく」**。

## 2. 目標・非目標・アンチゴール

### 目標
- フォルダを長押しで、中身ごと削除できる。
- Botのファイルが画面上で1か所に見える（今は「入退室音」と「入退室音（共有フォルダ）」の2つが並び、分かりにくい）。
- トークンなどは Bot のフォルダの `.env` ファイルに書く。フォルダを丸ごと持ってくれば `.env` も一緒に来る。
- ライブラリと部品（Python・Node.js）が入っているかが、ひと目で分かる。
- Botの削除は、いつもフォルダごと消す。

### 非目標
- アプリの中でのファイル編集（テキストエディタ）。ただし `.env` だけは例外（5.4）。
- 通話機能・ffmpeg（別の設計書で扱う）。

### アンチゴール（動いていても失敗とみなすもの）
- 削除の確認なしに、フォルダの中身が消えること。
- 動いている Bot のファイルを消して、Bot が壊れた状態で動き続けること。
- 既存の秘密の値が、移行で消えること。
- `.env` 以外の秘密っぽいファイル（`secure.key`、`.session`、`.db` など）が共有フォルダに出ること。

### 受け入れた危険（ユーザーが決定）
- **`.env` を共有フォルダに置く**。ユーザーの言葉:「.envを共有モデルに入れても問題ない」。
  - Android 8（ZenFone 4）では、ストレージの許可を持つアプリなら、どれでも共有フォルダの `.env` を読める。この危険はユーザーに伝えたうえで決定された。
  - 漏れたときは Discord の開発者ページでトークンを作り直す。

## 3. 今の仕組み（変えない部分）

- 実際に動くのは、アプリ専用の場所 `filesDir/bots/<id>/code` のファイル。共有フォルダ `Documents/PythonRunner/<Bot名>` はその写し。Android では共有フォルダのプログラムを実行できず、ほかのアプリからも書き換えられるため、この2か所の仕組みは残す。
- 共有フォルダで変更されたものは「✏ 変更あり」として知らせ、確かめてから取り込む（FolderSync）。
- `BotImporter.SKIPPED_FOLDERS`（`__pycache__`、`.git`、`venv`、`.venv`、`__MACOSX`、`node_modules`）は同期も取り込みもしない。

## 4. Botの削除

- 削除のダイアログから「一覧から外すだけ（フォルダは残す）」をなくす。削除すると、いつもアプリの中のファイル・ライブラリ・設定と、共有フォルダの両方を消す。
- ダイアログの文: 「『<Bot名>』を削除しますか？」「動いていれば止めます。ファイル・ライブラリ・設定と、共有フォルダ（ドキュメント › PythonRunner › <Bot名>）も消えます。元に戻せません。」
- 設定タブの「一覧から外すだけなら…」の説明文も消す。
- ストレージの許可がないときは共有フォルダを消せない。そのときは、残ったフォルダの場所をダイアログで伝える（今の動きのまま）。

## 5. ファイル画面

### 5.1 見え方（見本 1 のとおり）
- 左の「Bot / このスマホ（共有） / アプリ専用」の並びをなくし、**Botのファイルだけ**を見せる。上に「入退室音 › player」のような位置表示と「上へ」。
- 下に小さく「場所：ドキュメント › PythonRunner › <Bot名>（PC やファイルアプリからも同じ中身が見えます）」と書く。
- 「Documents」「Download」「内部ストレージ」「ライブラリ（pip）」「Python本体」の閲覧はファイル画面から外す（私の判断）。
  - 取り込みは「フォルダを取り込む」「ファイルを取り込む」ボタン（システムのファイル選択）で行う。
  - ライブラリはライブラリタブで見せる（7章）。
- `node_modules` と `.venv` は薄い色で「アプリが入れた部品」と表示する。中は開けてよいが、削除の対象にはしない（中身は「部品を入れ直す」で作り直すもの）。
- `.env` には鍵のマークと「トークンなど」の説明を付ける。

### 5.2 長押しの削除
- ファイルもフォルダも、長押しで削除の確認を出す。今のタップで出るメニュー（「これを最初に実行」など）は残す。
- 確認の文（フォルダ）: 「フォルダ『src』を中身ごと削除しますか？」「中の 7 個のファイルも消えます。共有フォルダからも消えます。」ボタンは「やめる」「削除する」（赤）。数はフォルダ以下のファイルの総数。
- Bot が動いている間、取り込みの途中、部品を入れている途中は削除できない。長押しすると「削除するには Bot を止めてください」と出す。
- 消した後、共有フォルダの写しからも消す。ただし、共有フォルダ側で書き換えられたファイルは消さずに残す（今の FolderSync の決まりのまま）。
- 「最初に実行するファイル」を含むフォルダを消したときは、「最初に実行するファイル」を未選択に戻す。

### 5.3 入れ替え（取り込み）

ユーザーは、中のフォルダ（`player` など）の入れ替えと、Bot まるごとの入れ替えの**両方**を使う（ユーザーの言葉:「両方ある」）。ユーザーに説明して了承を得た形:

> ① player だけ入れ替えたいとき：player を長押しして消す →「フォルダを取り込む」で PC の player を選ぶ → 元の場所に player が入る
> ② Bot まるごと入れ替えたいとき：「Botをまるごと入れ替える」を押す → PC の nyutaishitsu を選ぶ → 中身が全部新しくなる（スマホで登録した音は消さずに残す）

**「フォルダを取り込む」（①）**
- 選んだフォルダを、**ファイル画面でいま開いている場所に、同じ名前のフォルダとして**入れる。今は中身が Bot の一番上に広がるので、ここを変える。
- 同じ名前のフォルダがすでにあれば、②と同じ確認画面を出す（対象はそのフォルダの中だけ）。
- 「ファイルを取り込む」（.py・ZIP など 1 つのファイル）も、いま開いている場所に入れる。ZIP の扱いは今のまま（中身を広げる）で、広げる先をいま開いている場所にする。

**「Botをまるごと入れ替える」（②）**
- ファイル画面に置く。押すとフォルダか ZIP を選ばせ、その中身を Bot の一番上にする（今の「フォルダを取り込む」の動き）。
- 確認画面には次の 3 つを分けて出す:
  1. 置き換わるもの・増えるもの（今の確認画面）
  2. **新しいフォルダにないもの**。一覧で見せ、「残す」「消す」を選べる。**最初は「残す」**（私の判断）。スマホで登録した音（`data/sounds.dat`、`sounds/…`）は PC のフォルダにないので、うっかり消さないため。
  3. 一覧に出さず、いつも残すもの: アプリの中だけのファイル（`secure.key` など秘密っぽいもの。`.env` は除く）と、アプリが入れた部品（`node_modules`・`.venv`）。
- 取り込みの途中で失敗したら、今の取り込みと同じく元に戻す（`BotImporter` の印とバックアップの仕組みを、消すファイルにも使う）。
- Bot が動いていたら、今の取り込みと同じ扱い（止めてから入れ替え、終わったら起動し直すかを聞く）。

### 5.4 `.env`
- `.env` は Bot のフォルダの一番上の `code/.env` に置く。
- **同期**: 名前がちょうど `.env` のファイルだけ、秘密っぽいファイルの扱いから外し、ほかのファイルと同じように共有フォルダと行き来させる。`.env.local` などの変種と、`.key`・`.session`・`.db` などは今までどおりアプリの中だけ。
- **取り込み**: フォルダや ZIP を取り込むとき、`.env` も一緒に取り込む。ホームの「見つかったフォルダ」を追加する（`SharedFolders.adoptableFiles`）ときも `.env` を連れてくる。
- **初めての同期**（移行と同時に行う。私の判断。どちらの `.env` の値も失わないため）:
  1. アプリの中に `.env` がなく、共有フォルダにあれば、まず共有フォルダの `.env` をアプリの中へ写す。
  2. そこに今の秘密の値のうち、まだない名前を足す。
  3. できた `.env` を共有フォルダへ写し、同期済みとして記録する。両方にあって中身が違うときは、アプリの中の `.env` に、共有フォルダの側にしかない名前を足してから写す（同じ名前はアプリの中の値を残す）。
- **起動時**: アプリが `code/.env` を読み、中の値を環境変数として Bot に渡す。Bot 自身が python-dotenv などで `.env` を読んでも同じ値になる。
  - 書き方は一般的な dotenv の形に合わせる: `KEY=VALUE`、`#` で始まる行はコメント、前後の空白は無視、値の `"…"`・`'…'` は外す、先頭の `export ` は無視。
  - 読めない行は飛ばし、ログに「.env の n 行目を読めませんでした」と出す（値は出さない）。
- **設定タブ**: 「秘密の値」の欄を、**`.env` の欄**に置き換える（私の判断。スマホだけで `.env` を作れる場所が必要なため）。
  - ふだんは書かれている名前だけを見せる（例: `DISCORD_TOKEN ●●●●`）。
  - 「表示して編集」を押すと、`.env` の中身を複数行の入力欄で直せる。
  - 保存で `code/.env` に書き、共有フォルダにも写す。
  - `.env` がないときは「まだありません」と「作る」ボタン。
- **移行**: 今の「秘密の値」（BotStore の envVars）を、アップデート後の最初の起動で `.env` に移す。
  - `.env` がなければ作る。あれば、`.env` にない名前だけを末尾に足す。
  - 移し終えたら envVars を消す。移す前に失敗したら envVars は残し、次の起動でやり直す。
- ログに `.env` の値を出さない（今の秘密の値と同じ扱い）。

## 6. 部品（Python・Node.js）

試作の「部品をまとめて入れる」（`BotParts`、`BotController.runBotParts`）を正式な機能にする。中身は試作のまま:

- `requirements.txt` ごとに `pip install -r` でBotのライブラリ置き場に入れ、その隣に `.venv/bin/python`（アプリの Python へのリンク）を置く。
- `package.json` ごとに `npm ci`（lockfile があるとき）か `npm install`。`--ignore-scripts`。

変える点:
- ボタンの名前は「部品を入れ直す」（初めてのときは「部品を入れる」）。
- **Bot が動いていたら自動で止め、終わったら起動し直す**。今のように「先に止めてください」とは言わない。止めていた Bot は止めたままにする。
- 入れ終えた時刻を部品ごとに記録する。

## 7. ライブラリタブ（見本 2 のとおり）

一番上に「入っているもの」を出す。
- **Python のライブラリ**: Bot のライブラリは 1 か所（`libs/`）にまとめて入るので、一覧は 1 つ（私の判断）。
  - 中身はライブラリ置き場の `*.dist-info` から読んだ名前と版。3つまで出して「ほか n 個」、押すと全部。
  - 見出しに、`requirements.txt` ごとの状態を並べる（例「bot/requirements.txt ✓ 11/12 入れました」）。
- **Node.js の部品**: `package.json` のあるフォルダごとに、フォルダ名と日付を出す。その下に、`package.json` の dependencies の名前と `node_modules/<名前>/package.json` の版（3つまで + 「ほか n 個」）。
- **状態の決め方**（私の判断）:
  - ✓ 入っています：入れた記録があり、実物もある。Python は `.venv/bin/python` のリンク、Node.js は `node_modules` が実物。
  - ✗ まだ入っていません：記録がないか、実物が消えている（フォルダを消して取り込み直したときなど）。
  - ! 入れ直してください：入れた後で `requirements.txt` や `package.json` が変わった（ファイルの更新時刻が入れた時刻より新しい）。
- ✗ か ! が 1 つでもあれば、色を付けてボタンを「部品を入れる」にする。
- `requirements.txt` も `package.json` もない Bot では、この欄を出さない。

その下に「ほかのライブラリを足す」（今の pip install の欄）。
- 入力したライブラリがすでに入っていれば「discord.py 2.6.4 は入っています（押すと最新にします）」、なければ「requests はまだ入っていません」と入力欄の下に出す。

## 8. 決めたことのうち、ユーザーが決めたもの
- フォルダは長押しで中身ごと削除。
- 入れ替えは、中のフォルダ（①）と Bot まるごと（②）の両方。
- Botの削除はフォルダごとだけ。
- 秘密の値をやめて `.env` にする。`.env` は共有フォルダに入れてよい。
- ライブラリは「入っているもの」を版付きで見せる。
- ファイル画面とライブラリ画面は、見本 1・2 のとおり。

## 9. 私の判断（ユーザーに確認してもらうもの）
- `spike/node` の上で作り、`main` にはまだ入れない。Node.js 同梱を正式にする作業（`main` へ入れる準備）は、通話機能の設計書で扱う。
- 初めての同期で、アプリの中と共有フォルダの `.env` を合わせる（5.4）。
- 部品の状態を「記録 + 実物 + 更新時刻」で決める（7章）。
- ファイル画面から Documents・Download・内部ストレージ・ライブラリ・Python本体の閲覧を外す。
- 設定タブに `.env` の簡単な編集欄を置く。
- `node_modules`・`.venv` は削除の対象外。
- 「Botをまるごと入れ替える」で、新しいフォルダにないものは最初「残す」にする。

## 10. 作る人に任せること
- 画面の細かい配置・色（今のアプリの見た目に合わせる）。
- `.env` の読み込み処理の置き場所とテストの書き方。
- 「入っているもの」の読み取りを、いつ・どのスレッドで行うか（画面を固めないこと）。
